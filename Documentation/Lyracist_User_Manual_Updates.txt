Lyracist Pro Suite & KSRotation: Hybrid GPS & Wi-Fi Venue Auto-Location (`KSRotation`, `KSRotation.Maui`, `Lyracist`) - (September 2026)

Section: Lyracist & KSRotation / Venue Management / Hybrid GPS & Wi-Fi Venue Auto-Location

[Overview & Purpose]
Professional DJs and karaoke hosts frequently perform at multiple venues. In many venues, house Wi-Fi is either unavailable or unreliable, prompting hosts to use a portable travel router. Because a travel router broadcasts the same SSID and password everywhere, traditional Wi-Fi-based venue detection fails. Lyracist Pro, KSRotation, and KSRotation.Maui now feature a hybrid auto-location system combining high-precision GPS coordinate detection (with an adaptive 150-meter radius threshold) as the primary ground truth, with house Wi-Fi SSID as a secondary fallback. The system automatically selects recognized venues on startup and prompts to record new venue coordinates when arriving at a new location.

[Key Capabilities & Workflow]
1. Primary GPS Proximity Matching:
   - Evaluates physical geographic coordinates (Latitude and Longitude) using the Haversine spherical distance formula (`GeoMath`).
   - If the current position is within 150 meters of a known venue recorded in `Settings/ksrotation_venues.json` (or `venues.json`), that venue is automatically selected as the active venue.
2. Travel Router Immunity:
   - When using a portable travel router, DJs can mark the active network as a "Travel Router" in KSRotation.Maui's About dialog.
   - Flagged travel router SSIDs are registered in `Settings/ksrotation_travel_routers.json` and excluded from Wi-Fi venue matching, preventing the system from erroneously selecting an old gig location just because the travel router is connected.
   - House Wi-Fi SSIDs without travel router flags continue to serve as a fast secondary fallback when GPS hardware is offline.
3. Tablet-to-Laptop GPS Sync:
   - Laptops running Windows often lack dedicated GPS satellite hardware. Companion Android tablets running KSRotation.Maui capture hardware satellite coordinates and automatically push them to the host laptop via `POST /api/venue/location`.
   - The host laptop caches these peer-synced coordinates in `WindowsLocationService`, allowing the desktop apps to perform pinpoint venue matching even without onboard laptop GPS.
4. User Controls & Tagging:
   - "📍 Tag GPS" Button: Located in KSRotation (Settings / Venue Management), Lyracist (Settings / Venues tab), and KSRotation.Maui (About dialog). Clicking the button tags the currently detected GPS coordinates and active Wi-Fi SSID directly to the selected or entered venue name.
   - Startup Auto-Detection: On application launch, location detection runs automatically in the background. If a known venue is detected, the venue dropdown and settings update seamlessly without requiring manual intervention.
   - New Venue Auto-Save: If a new venue name is entered and tagged, it is automatically appended to the venue database with its coordinates and radius.

Store Plugin API: Modular Provider Architecture, Extensible Registry & Multi-Vector Fingerprinting (`Lyracist` ONLY) - (September 2026)

Section: Lyracist / Karaoke Store & Licensed Track Import / Store Plugin API (Lyracist ONLY)

[Overview & Purpose]
The Store Plugin API establishes a modular, extensible plugin architecture for the Lyracist Store ecosystem. Commercial karaoke providers (Karaoke Version, Party Tyme, Sunfly, Karaoke.com, and future additions) are encapsulated as independent, self-contained plugins adhering to the `IStoreProvider` interface. This architecture centralizes search URI generation, filename heuristics, ZIP archive inspection, CDG binary header matching, ID3 tag identification, and MP4 container metadata analysis into dedicated provider modules managed by a thread-safe `ProviderRegistry`.

[Architecture & Core Components]
1. `IStoreProvider` Interface:
   - `string Name { get; }`: Display title of the commercial provider (e.g., "Karaoke Version").
   - `ProviderSource Source { get; }`: Provider origin enum value (`KaraokeVersion`, `PartyTyme`, `Sunfly`, `KaraokeCom`, `Local`).
   - `Uri BuildSearchUri(string query)`: Formats deep search URLs for catalog queries or homepages.
   - `bool DetectFromFilename(string filename)`: Evaluates filename and title/artist heuristic patterns.
   - `bool DetectFromId3(FFprobeResult metadata)`: Evaluates ID3 audio tags (e.g. TXXX frames).
   - `bool DetectFromZip(string zipPath)`: Scans internal archive hierarchy and file pair layouts.
   - `bool DetectFromCdgHeader(byte[] header)`: Matches initial CDG magic header bytes.
   - `bool DetectFromMp4(FFprobeResult metadata)`: Analyzes MP4 stream metadata and container tags.

2. `BaseStoreProvider` Abstract Base Class:
   - Provides default `false` implementations for all detection methods, allowing plugins to override only their supported signatures.
   - Encapsulates safe ZIP entry enumeration (`MatchesZipEntries`), ID3 tag scanning (`MatchesId3Tags`), and MP4 metadata inspection (`MatchesMp4Metadata`).

3. Concrete Store Providers:
   - `KaraokeVersionProvider`: Search URL for karaoke-version.com, detection of `/custom_backing_track/` or `track.mp3`+`track.cdg` pairs, `KV` prefix/tags, and CDG magic header bytes `0x01 0x0F`.
   - `PartyTymeProvider`: Search URL for partytyme.net, detection of `/karaoke/` folders, `_pt.` naming, `PT` tags, and CDG magic header bytes `0x02 0x0A`.
   - `SunflyProvider`: Search URL for sunflykaraoke.com, detection of `sf` entry prefixes, `SF` tags, and CDG magic header bytes `0x03 0x0C`.
   - `KaraokeComProvider`: Search URL for karaoke.com, detection of `kcom` signatures, and ID3/MP4 metadata watermarks.

4. `ProviderRegistry` Central Registry:
   - Maintains a thread-safe catalog of registered provider plugins.
   - Supports dynamic registration via `RegisterProvider(IStoreProvider)`.
   - Provides unified multi-vector discovery APIs: `DetectProviderFromFilename`, `DetectProviderFromZip`, `DetectProviderFromCdg`, `DetectProviderFromId3`, and `DetectProviderFromMp4`.
   - Directly drives background download watcher ingestion, Bulk Import Wizard classification, Store Sync verification, and StoreViewModel search button generation.

Track Preview Player: Audio Inspection, Visualizations & Dual-Channel Auditioning (`Lyracist` ONLY) - (September 2026)

Section: Lyracist / Karaoke Store & Licensed Track Import / Track Preview Player (Lyracist ONLY)

[Overview & Purpose]
The Track Preview Player provides instant audio-visual inspection and acoustic verification for newly downloaded or cataloged karaoke purchases before or after library import. Integrated seamlessly within the Recent Imports audit grid on the Store tab and the Bulk Import Wizard candidate review list, the preview player allows host DJs to quickly audition tracks, verify audio quality, preview CDG/MP4 video streams, inspect spectral dynamics, and toggle dual-audio vocal channels without launching full karaoke playback sessions.

[Acoustic & Video Preview Engines]
1. 5-Second Rapid Audio Preview:
   - Powered by asynchronous FFmpeg stream extraction: extracts the opening 5 seconds of the source track into an uncompressed WAV or MP3 stream stored safely in the system temporary directory.
   - Built-in lightweight playback engine utilizes WPF MediaPlayer with accurate millisecond progress tracking, auto-rewind on completion, and manual scrub capability.
   - 1-click Play/Pause toggle with real-time elapsed time display (00:00 / 00:05).

2. Dual-Audio Channel Auditioning (Channel A / Channel B):
   - Multi-channel stream detection automatically flags dual-audio tracks (such as Party Tyme or Karaoke Version multiplex files featuring lead vocals on one stereo channel and instrumental backing on the other).
   - Interactive channel toggle:
     • Channel A (Guide Vocals): FFmpeg isolates and routes the left channel (c0) across stereo outputs (`pan=mono|c0=c0`) for vocal guidance verification.
     • Channel B (Instrumental): FFmpeg isolates and routes the right channel (c1) across stereo outputs (`pan=mono|c0=c1`) for backing track rehearsal.
   - Switching channels dynamically re-extracts the 5-second preview and resumes playback seamlessly.

3. Waveform Peak Visualization:
   - Generates and renders a high-contrast visual PNG waveform representation using FFmpeg `showwavespic`.
   - Allows hosts to visually inspect audio transients, identify dead air lead-in, and gauge dynamic range at a glance.

4. High-Resolution Spectrogram Visualization:
   - Generates a spectral acoustic density map using FFmpeg filter `showspectrum=s=800x300:color=intensity`.
   - Visually reveals frequency distribution across bass, midrange, and treble spectrums, highlighting audio fidelity, clipping, and high-frequency compression artifacts.

5. MP4 Video Stream Preview:
   - For MPEG-4 karaoke video files, FFmpeg extracts the opening 5-second video clip (`-ss 0 -t 5 -c:v libx264 -preset ultrafast -c:a aac`).
   - Rendered directly inside an embedded WPF MediaElement with hardware-accelerated playback and looping control.
   - Allows immediate visual verification of lyrics animation, title screen graphics, and video resolution.

[Technical Metadata Inspection Dashboard]
The Track Preview Player displays an organized technical badge dashboard highlighting critical musical and audio metadata:
- Filename & Source Provider: Clean canonical naming alongside color-coded provider tag (Karaoke Version, Party Tyme, Sunfly, Karaoke.com, or Local).
- File Type & Container: Format badge indicating MP3G, ZIPCDG, MP4, or Audio.
- Track Duration: Total song playback length formatted as mm:ss.
- Musical Key & BPM: Detected musical key signature (e.g. C, G, Am) and tempo beats-per-minute.
- Stream Quality & Difficulty: Fidelity rating (High, Medium, Low) and performance difficulty tier (Easy, Medium, Hard).
- Vocal Presence: Classification indicating guide vocals, background vocals, or clean instrumental.

[Trigger Points & Integration]
- Store Tab (Recent Imports): Selecting any row in the Recent Imports grid or clicking the dedicated "Preview" button in the Action column instantly displays the Track Preview Player below the table.
- Bulk Import Wizard: Selecting any candidate track in the import review data grid automatically loads its preview, allowing hosts to verify tracks before committing bulk import operations.

Store Tab Provider Intelligence & Advanced Fingerprinting (`Lyracist` ONLY) - (September 2026)

Section: Lyracist / Karaoke Store & Licensed Track Import / Provider Intelligence (Lyracist ONLY)

[Overview & Purpose]
Provider Intelligence introduces multi-tier forensic fingerprinting into the Lyracist Store import pipeline. When karaoke tracks are imported (via folder watcher or manual import), Lyracist inspects the physical file contents, container structures, and metadata tags to accurately determine the source provider—specifically Karaoke Version, Party Tyme, Sunfly, and Karaoke.com—without relying solely on basic filename patterns.

[Fingerprinting Methodology Hierarchy]
The import pipeline evaluates incoming media through a prioritized 6-tier detection hierarchy:
1. ZIP Internal Signatures (ZIP Inspection):
   - Scans central directory and local headers of .zip archives without extracting to disk.
   - Karaoke Version: Detected by presence of `/custom_backing_track/` directory, exact `track.mp3` + `track.cdg` pair, or "KV" / "Karaoke Version" tokens.
   - Party Tyme: Detected by `/karaoke/` folder structure, `_PT` / `- PT` filename suffixes, or "party tyme" markers.
   - Sunfly: Detected by `SF` prefixed CDG filenames or "sunfly" folder/filename markers.
   - Karaoke.com: Detected by `KCOM`, `KARAOKECOM`, or `karaoke.com` filename/folder indicators.
2. CDG Binary Header Fingerprinting:
   - Reads the first 24 bytes of standalone or unzipped `.cdg` graphic stream files.
   - Karaoke Version: Signature bytes `0x01 0x0F`.
   - Party Tyme: Signature bytes `0x02 0x0A`.
   - Sunfly: Signature bytes `0x03 0x0C`.
3. MP3 ID3 Tag Fingerprinting:
   - Uses FFprobe to inspect ID3v2 user-defined text frames (TXXX) and comment frames.
   - TXXX:KV / TXXX:KaraokeVersion -> Karaoke Version.
   - TXXX:PT / TXXX:PartyTyme -> Party Tyme.
   - TXXX:SF / TXXX:Sunfly -> Sunfly.
   - TXXX:KCOM / TXXX:Karaoke.com -> Karaoke.com.
4. MP4 Container Metadata Fingerprinting:
   - Inspects container-level metadata (title, artist, comment, publisher, copyright, and custom tags) via FFprobe.
   - Detects brand watermarks and provider names: "Sunfly", "Party Tyme", "Karaoke Version", and "Karaoke.com".
5. Filename Pattern Heuristics (Fallback):
   - Evaluates standard naming conventions (e.g. `KV*`, `*Party Tyme*`, `SF*`, `KCOM*`).
6. Provider Referrer Hint (Fallback):
   - Remembers the last provider search button clicked in the Store tab during the current session, attributing downloads to that provider if all internal file signatures are neutral.

Section: Lyracist / Automatic Volume Normalization

Section: Lyracist & KSRotation & KSRotation.Maui / Linked Singers

[Two Singers, One Slot in Line]
1. Linking Two Singers:
   - Click the 🔗 button on a singer, then click 🔗 on a second singer, to link them together - a blue "🔗 [partner name]" badge appears next to both names.
   - Once linked, the two always stay adjacent in the rotation: no other singer can land between them, whether from a new signup, a drag/drop reorder, or the Move Up/Down buttons.

   - When one half of a linked pair finishes their song, they float to the bottom of the rotation (with "Float Current Singer to Top" on) exactly like any other singer, while their partner is promoted to sing next - performing back-to-back, which is the whole point of linking them. This is a brief, expected exception to the "always adjacent" rule, not a bug.
   - Once BOTH halves of the pair have had their turn, they are automatically pulled back together to wait adjacently for their next joint turn - the DJ never needs to re-link them.
3. Linked Singers and Pause/Inactive:
   - Pausing one half of a linked pair does not break the link and does not move it out of place - a paused singer simply keeps its spot and is skipped over when its turn comes, exactly like any other paused singer, and its partner still stays right next to it.
   - Marking one half of a pair Inactive ("out for the night") is different: the still-active partner is NOT forced to follow the retired singer down into the inactive section.
